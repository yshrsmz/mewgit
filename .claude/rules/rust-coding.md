# Rust のコーディング規約

`CLAUDE.md` の「コーディング規約」の続き。どれも実際に踏んで `/simplify` か `/code-review` に拾われた形で、根拠の PR 番号を添えてある。

- **`cargo fix` は、`#[cfg(test)] mod tests { use super::*; }` が使っている import を
  ヘッダから消すことがある。** lib ユニットは `cfg(test)` を切って検査するので、テスト
  からしか届かない import が「未使用」に見え、その判断が同じソースに書き戻されて test
  ユニットが落ちる（`--all-targets` を付けても防げない。#75 で `app/update.rs` を
  割ったときに 216 エラー）。
  **道具が壊れているのではなく、ヘッダがテスト専用の import を抱えている形が壊れている**
  ので、直すのは `cargo fix` の出力のほう —— **ヘッダは cargo fix に切り詰めさせ、
  足りなくなった名前を各 `mod tests` の `use` に足す**。そこまでやれば 2 回目以降の
  `cargo fix` は素直に効く
- **改行を含む文字列リテラルは 1 行で書く。行継続（`\` + 改行）を使わない。**
  `rustfmt` が畳むときに、次の行のインデントをリテラルの空白として残すことがある
  （確認モーダルの本文が「。」のあとに空白 17 個、という形で出る）。`contains` を見る
  テストは素通りするので、pty で動かすまで気付けない。テストのパッチも同じ理由で 1 行。
  **エディタ以外（スクリプトやヒアドキュメント）で書き込んだら、書いたあとに `grep` で
  1 行になっているかを見る** —— #63 ではこの規則を知っていながら破った。python の
  ヒアドキュメントに Rust を書いたので、`\n` がその場で実改行に化けて 3 つ入り込み、
  `/simplify` が拾うまで気付かなかった（**中身は同じなのでテストは全部通る**）
- **`AppState` にコールバック（関数ポインタ・クロージャ）を持たせない。** 確定後に何を
  するかは `Cmd` かデータの enum で表す。関数ポインタは環境をキャプチャできず文脈を
  運べないうえ、状態が `PartialEq` を失って遷移をテストできなくなる
- **「上流と同じ判断だ」と書く前に、上流が安全でいられる仕組みが自分の実装でも
  成り立つかを数える。** #45 では `-` 始まりのホストの拒否を「git 自身と同じ判断」と
  書いたが、git 2.55 が拒むのは `user@host` **全体**が `-` 始まりのときだけで、
  `git@-4:a/b.git` は素通りする。git が安全なのは `git@-4` を 1 語のまま ssh に渡す
  からで、`user@` を捨てるこちらだけが裸の `-4` を作っていた。**受け継いだ危険ではなく、
  こちらが作った危険。** 上流に合わせて緩める読み方ができる状態になっていた。
  **もう 1 つの形は「上流が明示的に断る場面を、こちらが組む argv が回避する」。**
  #47 では素の `git push` が `push.default = simple` でローカル追跡を断るのに、
  こちらが組んだ `git push . topic:main` は**ネットワークに出ないままローカルの ref を
  早送りして exit 0** で返った。**doc に「上流が断るのと同じ理由」と書いた、その守りを
  自分の argv が外していた。** 上流の拒否を根拠に書くなら、自分が渡す形でもその拒否が
  効くかを実際に叩いて確かめる
- **守りを根拠に書く前に、その守りが何を守っているかを数える。** #49 の
  `--force-with-lease` は「**リモートが動いていないこと**」しか守らない。動いていない
  ことを `f` で自分で確かめたあとの force には、もう守りが無い。**自分が UI から案内する
  手順も経路** —— 01 に「`f` でリモートの位置を見てから `P`」と書いた回復手順は、
  `↓n` だけのブランチではそのまま破壊手順で、**出すものが 1 つも無いのに他人の
  コミットを消した**（一時リポジトリで再現。`ahead == 0` で断るようにした）。
  案内文を書いたら、別の状態でその手順を踏んだらどうなるかを数える。
  **数えるものには「どの順序なら拾えるか」も入る** —— #51 の世代（epoch）は
  「読みが飛んでいるあいだに書き込みが終わった」形しか拾えず、逆順（書き込みの最中に
  読みを頼み、読みのほうが先に返る）では刻印がまだ最新なので素通りする。
  `C`（amend）の本文はまさに逆順で、**設計書に「塞いだ」と書いた穴が開いたままだった**
  （`/code-review` が拾った。押した時点で断る形にした）
  **鍵が答えられる問いも数える** —— #89 の `(番号, head sha)` は「一覧のどの行に
  当てるか」しか答えず、**アカウントを切り替えても番号も head も変わらない**ので、前の
  トークンの答えが新しい一覧に入った。**#83 と #89 で 2 回続けて「鍵のほうが世代より
  強い」と読み違えて世代を見送った。**
  **数え落とすのは「守る範囲」だけではない** —— #83 の「ここが失敗からの*唯一の*出口」は
  材料の本数（ref だけでなくトークンも）を、#80 の `r` は届く範囲（mewgit の設定
  ファイルは起動時に固まる）を数え落としていた。
  **押せるキーだけを数えて「到達しない」と書かない** —— #101 ではモーダル表示中に
  `A` を押せないところまでは正しかったのに、**非同期の完了（`SetAccount` の書き込み）が
  同じ状態を動かす**ことを数えていなかった
- **案内にキーを書いたら、その案内が出ている画面でそのキーが効くかを数える。** 上の
  「別の状態で踏んだらどうなるか」の画面版。#53 では非 FF で断られた `-u` の push に
  「`r` で改名して push できます」と出したが、**`r` が効くのは Branches ペインの中だけ**
  で、既定のフォーカスである Graph では何も起きない。しかも `r` は**カーソル行**を
  改名するので、押した本人のブランチとは限らなかった（`/code-review` が拾った。キーでは
  なくペインの名前を出す形にした）。**キーマップがペインごとに割れている以上、
  「押せる」は画面ごとに数える。**
  **キーが無い版もある —— 案内が求める操作を、そもそも自分が持っているかを数える。**
  #63 では `f` の無反応を通知に変えたが、その通知が「追跡先を設定してください」と
  言うのに、**mewgit にリモートを指定する操作が無かった**（キーも一覧も無く、`P` も
  同じ関数を通るので `-u` の提案すら出ない）。しかも外で設定しても、ブランチ一覧を
  読み直すのは ref を動かす書き込みのあとだけなので再起動するまで効かない。
  **「無反応よりまし」で止めると行き止まりが残る**（#65 で選択モーダルを足した）。
  裏返して、**指示を足すのはその操作を持たない側** —— 選ばせるモーダルの本文に
  「外で設定してください」と書くと、いま提供している操作を外でやれと言うことになる
- **「押し直して」は 1 回に読める。案内が求める手順の回数まで数える。** #53 では
  force の失敗で記憶を落とすので、`f` のあと 1 回目の `P` は素の push になり、もう
  一度断られてから force の確認が出る。**途中で出る別の案内と食い違う**
- **読まれない状態を「断る」方向で直すと、その状態を落とす経路へ入れなくなることが
  ある。** #53 では `-u` の push で `push_rejected` が立つのに誰も読まない死んだ値
  だったので（`/simplify`）、`push_plan` が読んで断る形にした。ところが**断ると `P` が
  `GitOp::Push` を出さなくなり、記憶を落とす唯一の経路（`exec_finished`）へ二度と
  入れない** —— リモート側の同名ブランチが外で消えても断り続ける（`/code-review` が
  拾った）。正解は**憶えないほうを直す**こと。**状態を消すのが「その状態を根拠に断つ
  キー」の先にあるなら、断つ前に消し方を数える**
  **憶えること自体が入口の版** —— #89 では集計の `Err` を落とす経路が無く、
  **回線が 1 回切れただけでセッション中ずっと `!`** のままだった。しかも**既存テストが
  その「引き直さない」を仕様として固定していた**。失敗を憶える形は、落とす経路と
  セットで入れる
- **`None` の理由を 2 つ以上持たせない。** `None`（や `0`・空）が「まだ届いていない」
  「試したが失敗した」「そもそも無い」のうち 2 つを兼ねると、読む側が出し分けられない。
  分けるときは 3 値の `enum` にするか、失敗を `Result` で運ぶ。踏んだ形 —— #54 では
  `Diff` を候補から外す条件が「この行では永久に出せない」と「まだ届いていない」を
  混ぜていた（`testing.md` の「条件を狭めた変更で…」）。#86 では `Rows.cursor` の `0` が
  「先頭を選んでいる」と同じ値だった（下の「一覧を共有する 2 枚目を作ると…」）。
  PR の集計を `PullRequest` に `Option` で持たせないのも、取り直した候補一覧を 3 値に
  しているのもこの理由
- **旗と値を割らない。** #49 の `GitOp::Push` は `force: bool` と
  `expected: Option<Oid>` を別々に持っていたので、`force: true, expected: None`
  —— 値の無い `--force-with-lease`（#21 で「fetch 一発で無力化」と確認済み）が
  型で組めた。**1 つの `Option` に畳めば、その組み合わせは存在しない。**
  doc に「値を必ず添える」と書いても、型が許すなら踏める
- **導出できる値を引数に取らせない。** 上と同じ形が「別々のフィールド」ではなく
  「別々の引数」で出る。#51 の `is_fresh(asked, region)` は、`finish(LoadStatus)` の
  刻印を `Region::Log` と比べる形が組めた（常に「古い」になり、頼み直しを回す）。
  領域は `JobKind::region()` が持っているので、**種別だけ渡して中で引く**形にすれば
  誤った対はそもそも書けない。同じ理由で、値に添える刻印は**届いた返信のものを持ち越す**
  —— 取り直すと、読む側と書く側で刻印の出どころが 2 本になる
- **二値だった結果に 3 つ目を足したら、入口と出口の両方を数える。** #56 の中断
  （`ExecError::Canceled`）は「成功 / 失敗」の外側にある 3 つ目で、`/code-review` が
  両側を拾った。**入口** —— 「合図を撃った」と「その合図で終わった」は別。
  `tokio::select!` は両方 ready なら無作為に腕を選ぶので、中断を頼んだことを根拠に
  分類すると、**git 自身の失敗を中断として握り潰す**（原因は終了状態で確かめる）。
  **出口** —— 既存の 2 本の腕が前提していたことが 3 つ目で嘘になる。「失敗なら ref は
  元のまま」は、`git commit` が ref を書いてから hook を走らせる以上**中断では
  成り立たない**（中断でもコミットは済んでいることがある）。**予告した 2 つのうち
  `gh auth status` は実際に 3 値だった** —— ただし「ログイン済み / 未ログイン / エラー」
  ではなく `success` / `timeout` / `error`（**アカウントごとにトークンを検証した結果**。
  #61 で確認し、`LoginState` としてそのまま運んでいる）。**形は当たったが値は
  当てずっぽうだった**ので、残る M5 の rebase（成功 / 失敗 / コンフリクトで停止）も
  着手時に実物で数え直す
  **非同期スケジューリングの版** —— #89 では `JoinSet` に全件 spawn してから
  タスクの先頭で中止の旗を読む形が、**1 本も止められなかった**（切り離されたタスクは
  最初の応答より前に旗を読み終え、permit の列で待って順番が来れば叩く。
  `issued=60 / skipped=0`）。**「旗を立てた」と「止まった」は別**で、止めていたのは
  同時本数ではなく「抜けるとストリームごと落ちること」だった
- **上の規則は `enum` の腕を増やす形にも当たる。** #68 では `AttemptFailure` に
  `Undetermined`（断られてはいない）を足したのに、probe の出口は「通ったか」だけを
  数えていて、**確かめられなかった候補を「除外できた」と同じに扱った**。成功 /
  失敗 / 中断の形で書いた規則を、腕を 1 つ足した `enum` に当てはめて読めるかが要
- **手順を飛ばす近道を作ったら、飛ばした手順が持っていた入口を数える。** #68 の
  「明示指定があれば一覧を引かない」は 0.24 秒を節約する正しい最適化だったが、
  飛ばした手順が `gh` の失敗を `DegradedReason` に畳む唯一の入口でもあったので、
  **プロセス全体の条件（gh が古い）が login ごとの設定ミスの服を着て出てきた**
- **1 回きり決めて憶える値の材料に、別のジョブから届く値を混ぜない。** `.claude/rules/testing.md` は
  同じ話を**テスト側**でしか書いていなかった（「ループテストは非同期の返信が届く順序に
  依存できない」）。**踏んだのは production 側。** #63 の `RepoInfo.target` は 1 回きり
  決めて latch するのに、材料に `branch.<HEAD>.remote` を混ぜたので、
  **`Msg::BranchesLoaded` と `Msg::RepoInfoLoaded` のどちらが先に届くかで答えが変わり、
  二度と直らない**形になった（`/simplify` が拾った）。入口は「共有した規則」で、
  `f`（キー。遅れて届いた一覧は次に押したときに効く）に合わせて作った寛容さを、
  latch する読み手が引き継いでいた —— **共有先の暗黙の前提が新しい利用者にも成り立つか**
  （`ui::window` と同じ形）の、**前提が「時間」だった**版。
  **非同期の返信が 2 本あるなら、テストは両方の順序を回す。**
  **書き込む側も数える** —— 同じ #63 で `repo_info_loaded` が `Ok` / `Err` の両方から
  `resolve_target` を呼んでいたので、**読めなかっただけの一回**が「決められなかった」と
  して latch された（`/code-review` が拾った）。`Unasked` / `Resolved` / `Unavailable` に
  割ったこと自体は正しく、**割った意味を書き込む側が守っていなかった**
- **段を前に足したら、後ろの段が持っていた守りを迂回していないかを数える。** #63 の
  `default_remote` は 1 段目（`branch.<HEAD>.remote`）を 2 段目の手前に置いたので、
  2 段目が持つ「リモート一覧がまだ届いていない」の守りを飛ばし、ブランチ一覧だけが
  先に届いた瞬間に「追跡先の origin がリモートにありません」と**設定が壊れていると
  言った**（`/code-review` が拾った）
- **「守り」が守っている範囲を、名前ではなく実物で数える。** #65 では一覧を素の
  `Paragraph` で描いていたのを `ui::render_rows`（窓を切り出す）に直した**直後の版でも**、
  理由の段落に `Length` で絶対優先を与えていたせいで**一覧そのものが 0 行に潰れた**。
  `render_rows` が守るのは「カーソルが一覧の外へ出ない」ことで、**一覧が消えることは
  守らない**。症状はどちらも同じ（見えていない相手を `Enter` で選ぶ）。
  **「同じ穴をもう 1 回」は、直したときに書いた見張りが浅いことのサイン** —— 1 回目に
  書いた見張り（8 本 × 80x14）はこの形を踏めておらず、実機で境目（30 本 × 80x14 で
  0 行）を測るまでテストは緑だった
- **項目を既存の項目の直前に挿入すると doc コメントを奪う。** Rust の `///` は直後の
  項目に付くので、挿入した側が前の doc を連れていき、元の項目は無名になる。移動でも
  起きる（消したのが本体だけで doc が残ると、次の項目がそれを連れていく）。#40 で 3 回、
  #44 で 2 回、#49 で 1 回、#96 で 1 回。**挿入したら、その直後の項目の doc が残って
  いるかを見る**（`git show main:<file>` と突き合わせるのが速い）。
  **「関数」と読まない** —— #96 で奪われたのは `enum` の doc で、新しい `enum` を
  `TargetState` の直前に置いたせいで 15 行の設計判断が別の型の説明の頭に付いた。
  ここには長らく関数の例しか並んでいなかったが、`///` が見ているのは**直後の項目**
  であって種類ではない。**`cargo clippy` でも `cargo doc` の warning でも出ない**
  （`missing_docs` が無効なので）ので、疑うときは `cargo doc -p <crate> --no-deps` を
  流して**生成 HTML の top-doc を両方の型で突き合わせる**。
  **数千行を動かすときは目視で数えられないので、機械で突き合わせる。** 動かす単位を
  「doc コメント + 属性 + 本体」の塊にしたうえで、(a) 全部の塊が 1 度ずつ移ったか、
  (b) 全部の項目の doc が**元と同じ項目**に付いているか、を元ファイルと比べる。#75 の
  分割ではこれで 393 塊 / 391 項目を確かめた。**「元にしか無い行」を分類するのも効く**
  —— あそこで残ったのは `pub(super)` が付いて rustfmt が折り返した署名と import の
  断片だけで、本文が 1 行も消えていないことがそれで言えた
- **識別子を消す / 改名すると、差分に出ないファイルの記述が古くなる。** 上の doc 奪いが
  「同じファイルの中」なら、こちらは**触っていないファイル**の版。#86 では 1 行も
  触っていない `account.rs` が、消した識別子と変わった数を参照したまま 4 箇所嘘に
  なった。#98 では `head_home` → `head_homes` の改名で intra-doc リンク 1 本と
  テストのコメント 2 つが残った。**探し方は 2 つ** —— (a) 消した識別子と変えた数で
  `crates/` と `docs/` を grep する、(b) `cargo doc -p <crate> --no-deps
  --document-private-items` の `unresolved link`。**(b) は既存の警告に埋もれる**ので、
  `git worktree add` で main を切って同じコマンドを流し、**警告の数を比べる**
  （#98 ではどちらも 21 件で、この差分は増やしていないと言えた）。**コメントは語だけ
  でなく意味も古くなる** —— 畳んだ先に `None` が無くなっていたのに「`head_home` の
  `None`」と書いてあった。
- **スクリプトで範囲を切って消すときも、編集後の本数を期待値と突き合わせる。**
  「doc コメントを奪う」の項の「数千行を動かすとき」の**削除版**。#82 では「開始の
  関数名から次の関数名まで」で 4 本消すつもりが、**間に無関係な 3 本が挟まっていて 2 本しか消えず**、新しく書いた
  テストと重複したまま緑になるところだった。終端を `"}\n"` にして閉じ括弧が 1 つ
  余ったのも同じ回。**`cargo test` は前者では緑のまま通る**
- **モジュールを 1 段深くすると `super` の意味が変わる。** ずれるのは 2 つ ——
  `pub(super)` と intra-doc リンク。`app/update/mod.rs` の `super` は `update` では
  なく `app` なので、そこの項目に `pub(super)` を付けると「`app` から呼べる」という
  **別のことを言う**（子モジュールは private のままでも見えるので、そもそも要らない）。
  リンクも同じで、doc の `super::X` を指すリンクは 1 段浅い所を指したままになる。
  **private な項目への intra-doc リンクは解決しない**ので、リンクを生かすために
  `pub(super)` へ広げると**分割の目的と逆を向く** —— リンクを外してコードスパンにする。
  #75 ではこの罠を説明する文の中で自分も踏んだ（`cargo doc --document-private-items`
  の `unresolved link` が唯一の検出手段で、`cargo clippy` では出ない）
- **git の出力を文字列で分類するときは、行頭の形で見る。** git はコミットの件名を
  自分の出力に写す（`[main <oid>] <件名>`、`error: could not apply <oid>... <件名>`）ので、
  行のどこでも拾う照合は件名で取り違える。#137 では件名が `[head-moved] …` のコミットの
  コンフリクトを `HeadMoved` と読み、#139 では件名に `CONFLICT` を含むコミットを積んだ
  あとの空の停止を `Conflict` と読んで continue を案内した（どちらも `/code-review` が
  踏んだ）。**語を足すときは、その語が件名の位置に来た出力を 1 本テストに入れる**
  （`runner::classify` のテスト）。行頭の形は op ごとに一時リポジトリで叩いて確かめる
- **同じ判定を 2 箇所に書かない。** 「持っている詳細がカーソルのものか」は
  `GraphState::fresh_detail`、「カーソルが何を指しているか」は
  `GraphState::selection` の 1 つずつ。core（次に何を読むか）と ui（何を描くか）が
  同じものを使う。M1 の下部展開では「詳細の領域を取るか」を分けて書いていて、
  空グラフを展開すると行数が 10 行ずれていた
- **共有は半分だけになりやすい —— 出力を 1 本にしても入力が 2 本なら結果はずれる。**
  #18 では delta → 値型の写像を `git_read::file_entry` に寄せた直後に、**どの delta が
  存在するかを決める `find_similar` の設定**を `status` 側だけに残していた。
  「1 本にした」と書くときは、入口と出口の両方を数える
- **2 つ目の利用者が出た時点で共有先を作る。** 3 つ目まで待つと、そのあいだに 2 本が
  別々に育つ。#31 では統合テストの土台とファイル生成と Diff ペインの立ち上げ、#24 では
  窓の切り出しとカーソル移動の骨格とテストビルダー、#22 では中央寄せとカーソル行の反転が
  それぞれ 2〜3 本になっていた（**テストバイナリは別々にコンパイルされるので、テストの
  共有先は `test_util.rs`**）
  **読み取りの版もある** —— #107 では git_read に `remote_copies` を足したが、同じ
  `Msg::RepoInfoLoaded` が既に `RefIndex`（全 ref の名前と oid）を運んでいた（altitude が
  拾った）。**読み取りを足す前に、同じ返信で既に届いている値から導けるかを数える**
- **離れた場所に、コードの「いま N ある」を書かない。** 書かれた数は**導出できる値を、
  元から離れた場所に置いたコピー**で、「導出できる値を引数に取らせない」（上）と同じ形。
  **条件は「離れている」と「いま」の 2 語で、片方でも外れれば書いてよい** ——
  同じ段落で散文が並べる列挙の要約（「理由は 4 つある」+ 直後に 4 つ並ぶ。離れていない）と、
  過去形の実測（「起動 0.82 秒 → 2.04 秒」「境目は 30 本 × 80x14」。いまを主張していない）。
  **「近いから」では例外にならない** —— #54 でずれたのは 07 の「候補にあるのは ◯つ」で、
  数と列挙は同じ文にあったのに**列挙とコードのほうが**割れた。守れるのは
  **テキストの中で閉じた列挙**だけで、コードの状態を数えた列挙は隣に書いても腐る。
  #51 の `refs_again`（doc に「3 つで 1 つの関数にしてある」と書きながら**3 つ目が
  最初から通っていなかった**）、#75 の 00（`pub(super)` を `grep` して 37 と書いた
  あとに 1 つ private へ戻し、数え直さずに出した）、#77 の `remote.rs`（「`None` の
  4 つ目」は実際には 2 つ目、「断る腕は 4 つ」は 5 つ）——
  **最初から嘘だった数と、あとで嘘になった数の両方が出ている。**
  **数を書いてから同期を頑張る形にしない。**
  **「見落としを検出したい」から数を書きたくなったら、印を置いて一覧にする** ——
  各サイトに `// ` の印を置き、`grep` で一覧を出す（`update_inner` の「続きを頼む判断」が
  この形。印は `// 続きを頼む:`）。**これは導出ではなく索引**で、**印を忘れたサイトは
  古い数と同じだけ見えない**。だから**別の見方と突き合わせられる形にする** ——
  あそこは「`load_more` / `load_commit` / `load_diff` / `reload_log` /
  `JobTracker::is_fresh` の呼び出し元」と 1 対 1 になることを doc に書いてあり、
  印の漏れはそちらで出る。**`grep` のレシピにはパスを必ず書く**（省くと `target/` を
  舐めて返らない）。**収まらないサイトに印を付けたくなったら、それは索引の問題ではなく、
  そこだけ形が違うという合図**（#51 の「通せない理由があるなら共有すべきでない違い」
  の言い換え）
- **同じ事実でも、置かれる場所の予算が違うなら別の文言でよい。** 文言を 1 本に
  共有すると、**予算の狭いほうが広いほうを痩せさせる**。#73 ではヘッダの `[gh: …]`
  （リポジトリ名とスピナーと 1 行を分け合う）とモーダル（箱の中で折り返せる）の文を
  `/simplify` に「同じ文字列だ」と拾われて共有し、ヘッダを詰めた瞬間にモーダルの文が
  痩せた。上の「2 つ目の利用者が出た時点で共有先を作る」の例外側
  **1 箇所の予算を自分で食う形もある** —— #89 の `pr_row` の doc は「末尾に置くと黙って
  消えるから集計を前へ置いた」と書いたのに、**桁を 2 本足したことで今度は集計と
  タイトルが同じ消え方をした**（80x24 の右列は内側 30 セル）。**守りの理由は、桁や
  予算を足した瞬間に自分へ返る。** 同じ回に、上限の無い値（`InvalidHost` のホスト名）を
  要約行の `Display` に混ぜて `q:quit` を押し出した（理由は `Notice.detail` へ移した）
- **層をまたぐ述語は、その名前が約束している問いに誰が答えられるかで置き場所を決める。**
  `GitOp::moves_refs()` は stash を偽にしていて、その理由は「グラフが `refs/stash` を
  walk に押していない」という UI の都合だった（`app` の `update::Reload` へ移した）。
  逆に `valid_host` は「これはホスト名か」を答えるのでパーサ側でよい
- **共有先に寄せるときは、その基盤の暗黙の前提が新しい利用者にも成り立つかを確かめる。**
  `ui::window` は「カーソルが自己完結した 1 行」を前提にしていて、ハンクという塊を指す
  Diff ペインでは見出しが窓の下端に来て本文が 1 行も見えなかった。**doc コメントに
  「2 つのペインで同じものを使う」と利点として書いたことが、前提が壊れている事実を
  隠していた。** 共有を主張する文を書くときは、そこに前提を並べて数える。
  **共有を主張する文に、離れた場所の現在形の数を書かない**（上の項目）
- **候補の一覧を返す関数の先頭を、断定値に使わない。** 上の姉妹形で、**壊れている
  前提が「呼ぶ側が全部試す」**という doc に書きようの無いもの。#101 では
  `head_homes()`（「HEAD のブランチから出した PR の head が**在りうる**リポジトリを
  確からしい順に」返す。#98）の先頭を `POST /pulls` の `head` の owner に使ったが、
  **一覧が一覧である理由は答えが 1 つに決まらないこと**なので、その理由がそのまま
  誤った値になった —— `git clone <自分の fork>` → `git remote add upstream` →
  `git checkout -b feat upstream/main` は `branch.feat.remote` を **`upstream`** に
  するので（実測 2026-09-21、git 2.55、`env -i` の一時リポジトリ）、**自分の fork に
  push するつもりのブランチが upstream の owner で送られる**。
  **寛容な照合を良くする変更が、断定する側を悪くする**形なので読み手を分けた
- **一覧を共有する 2 枚目を作ると、1 枚目が自分で当てていたものが要件になる。**
  「共有先に寄せるときは…」の裏側。#86 では Branches と PRs で `Rows` / `TopPane` を共有したのに、カーソル行の
  反転だけがペイン側に残っていた。寄せたら `Rows.cursor` を `Option` にする必要が
  出た —— **文言 1 行のときの `0` が「先頭を選んでいる」と同じ値**で、反転させる側が
  答えられなかった。**共有先へ寄せる作業が `None` の 2 つ目の意味を炙り出す**
- **`enum` に変種を足したら、その `enum` を見る `match` を grep して `_` の腕を
  数える。** コンパイラが実装漏れを強いるのは**網羅な `match` だけ**で、受け皿の
  `_` を持つものは黙って飲む。#101 では `update::paste` だけが `_ => {}` で、
  `Modal::PrCreate` を足した回に**貼り付けだけが無反応**になった
  （`Modal::move_cursor` と `modals::render` は網羅なのでコンパイルエラーで気付く）。
  **テストでは出ない** —— 足した変種のテストを書くとき、その変種がまだ受けない
  入力のことは思い付かない。「見張りが実際には効いていなかった」の**コンパイル時版**で、
  規約の語（テスト・見張り）では引っかからない
- **状態に「どこから来たか」を足したら、読む側に既存の状態と 2 段で見させない。** 解いた
  `enum` を 1 本の関数から返し、読む側はそれを網羅 `match` する。#129 では Diff ペインに
  `DiffSource`（`Selection | Stash(Oid)`）を足し、出す diff・巡回の候補・`Esc` の戻り先・
  `s` / `u` / `x` の可否の **4 箇所がそれぞれ「stash なら先に、そうでなければグラフの
  選択」を書いた** —— 出どころを足してもコンパイラが何も言わず、段の順序を 4 箇所で守る
  形だった（`/simplify` の altitude が拾い、`AppState::diff_origin()` が
  `Worktree | Commit | Stash` を返す形にした）。`RightTab` が `Pane` を持たないのと
  同じ理屈で、**注釈や順序の約束を型にする**
- **世代が進まない引き金から、`AppState::issue` に落とされうる `Cmd` を出すときは、
  自前の追いつきを持つ。** #51 の世代（`Region`）が見ているのは「**書き込み**が何を
  古くするか」だけで、**書き込み以外の引き金は世代を進めない**。#101 の PR 作成は
  ローカルの ref を動かさないので、一覧の引き直しが同種実行中で落とされたとき
  `pr_list_loaded` の `is_fresh` が一度も走らず、**作った PR が画面に出ないまま**に
  なった（`/code-review` が probe 付きで実証）。**「落とされても詰まらない」は
  世代か鍵のどちらかが拾える場合の話**なので、どちらも拾えない引き金を足したら、
  そこで拾う手（`PrState::list_behind`）を一緒に足す。**その手は 1 回きりにする**
  —— 当たらないたびに頼み直すと、対象が永久に現れない形で同じ往復を回す
