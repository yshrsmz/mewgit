# 報告

- **長い作業は途中経過を報告する。** 調査・実装・レビュー待ちが数ターンにまたがるときは、
  節目ごとに「何をやったか」「いま何が走っているか」「次に何をするか」を出す。全部終わって
  から一度に出さない。バックグラウンドのエージェントや CI の完了待ちも、待っていること自体を
  報告する。
- **一区切りの報告には「CLI アプリとして動作確認できる機能が増えたか」を必ず含める。**
  増えていないなら「増えていない」と明言し、いま起動すると実際に何が見えるのかを書く。
  テストが通っていることと、ユーザーが触れるものが変わったことは別。
  - core の型と読み取り層だけが積み上がる期間が長いと、進捗の実感と実態がずれる。
    M0〜M1 前半がまさにそれで、`main.rs` に配線されないまま数 PR が進んだ
  - 報告の前に実際にバイナリを動かして確かめる。手順は `CLAUDE.md` の pty の節。
    パイプ渡しでは `enable_raw_mode` が落ちるので `script` + `stty` が要る
- 見送った判断・直さなかったレビュー指摘は、理由を添えて報告に残す。PR 本文にも書く。
