# 引き継ぎメモ

- 作業の進捗は `handover.local.md` に記録する。gitignore 対象のローカルファイルなのでリポジトリからは辿れない。なければ作る。
- 更新するのは、方針を決めたとき・タスクを完了したとき・環境の注意点が判明したとき・保留が解けたときの 4 つ。都度の作業ログではなく「次のセッションが知る必要のある状態」を書く。
- `docs/plan.md` と重複させない。`docs/plan.md` はタスクの一覧、`handover.local.md` は現在の状態と決定事項。
- `CLAUDE.md`・`.claude/` や `docs/design/` に書けるものは、そちらに書いて `handover.local.md` からは消す。`handover.local.md` は gitignore 対象で、他の環境にも他の contributor にも届かない。
- **保留を書いたら、解けたときに消す。** 「〜に据え置き」「〜のマージを待つ」の類は、その状態が解けたときに誰も直さない。#66 の整理では「`reqwest` だけ 0.12 に据え置き」（#59 で上げ済み）と「#63 のマージを待つ」（マージ済み）が逆を向いたまま残っていた。上の引き金に「保留が解けたとき」が入っているのはこのため。
- **`docs/plan.md` にタスクを足した / 順序を変えたら、`handover.local.md` の「次にやること」を突き合わせる。** 上の引き金 4 つは「タスクを完了したとき」までしか見ておらず、**完了したタスクが新しいタスクを生んだとき**に抜ける。#73 では残した穴を plan.md の M4 に挿入したのに、handover は「次は `ui::panes::prs`」のままだった。**正は `docs/plan.md`**（`CLAUDE.md` が「着手中のタスクはここで確認する」としている）。
- **PR ごとに 1 行増えるリストは、教訓の類型ごとに畳む。** PR 番号は根拠として残す。畳まないと PR のたびに線形に伸びて読まれなくなる。新しい類型が出たときだけ項目が増える形にする。
- **「handover を整理して」の本体は、規約や設計書へ移すこと。** 中の重複を畳むだけで終えない。上の「`CLAUDE.md`・`.claude/` や `docs/design/` に書けるものは、そちらに書いて消す」がそのまま整理の手順になる。2026-09-26 には「リポジトリの変更になるから」と移動を対象外にして、ユーザーに「なんで対象外なの」と聞き返された。docs だけの PR は確認なしで立ててよい手順（`CLAUDE.md` の「PR を作る前に」）なので、対象外にする理由にならない。
- **いまの機能の一覧や、どの PR がどのタスクだったかを書かない。** どのタスクが入ったかは
  `docs/plan.md` のチェック、キーごとの挙動は 07 の「既定キーバインド」と 01 の各節が持つ。
  2026-09-29 までは「いま動くもの」（約 90 行）を置いていたが、現在形の写しなので PR ごとに
  古くなった（`m` の skip も「80 桁で落ちるのは `L` だけ」も直し忘れた）。**報告で要る
  「CLI で何が見えるか」は、一覧を読むのではなく pty で実物を動かして答える**
  （`.claude/rules/reporting.md`）。07 にあった「どこまで実装したか」の表も同じ理由で消した
