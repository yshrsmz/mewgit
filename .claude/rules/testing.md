# テストの規約

`CLAUDE.md` の「テスト」の続き。見張りを足す・削る・変異で確かめるときに読む。

- **`cargo test --workspace` が返るまでの経過時間は、テストの実行時間ではない。**
  #82 で測ったところ、cargo が報告する実行時間（出力の `finished in`）の合計は
  **3.4 秒**（lib の 470 件で 0.16 秒）なのに、**ビルド済みでも経過時間は 20 秒**だった。
  差はほぼ cargo 自身のオーバーヘッドで、テストを減らしても動かない。
  **速さを根拠に何かを決めるなら `finished in` のほうを見る。**
- **設計書やコメントに「こう動く」と書いた振る舞いは、その手順を踏むテストで固定する。**
  コーディング規約（`rust-coding.md`）の「**守りを根拠に書く前に**、その守りが何を守っているかを数える」の
  裏側 —— **危なくないと思って書いた記述にも実装は追いつかない。** #56 では設計書と
  コメントの両方に「2 回目の `Ctrl-C` で終了する」と書いたのに、実装は中断を返し
  続けていた（`/simplify` が拾った）。git が SIGTERM で死なないあいだ、モーダル表示中は
  脱出口が無い。**手順を踏むテスト**
  （1 回目で中断 → 2 回目で終了）が無ければ、その記述は誰も見張っていない
- **回す組み合わせが「見張りが無ければ通る」ものかを数える。** #31 では鮮度ガードの
  テストが `['s','u','x']` を回していたが、Unstaged の `u` は鮮度に関わらず区画で
  断られるので、その腕は見張りを踏んでいなかった。**通る組み合わせを足しても
  見張りは増えない。**
- **共有した見張りは、新しい産出元を自分では拾わない。** 産出元が 2 つになったら、
  見張りが全部を通っているかを数える。#40 では `ui::LOADING`（複数のペインが出す文言）を
  画面全体の `contains` で見ていたので、新しいペインが出した時点で既存の見張りが 2 つ
  死んだ。#42 では確認モーダルの本文を組む場所が 2 つになったのに、畳み込みインデントの
  見張りは worktree の discard しか回していなかった。**どちらもテストは全部通っていた**
- **見張りが回す範囲を実装側の集合から導いていると、集合を狭めた瞬間に腕が黙って
  減る。** 上の裏返し。#54 では枠の太さを見るテストが回すペインを
  `AppState::focus_candidates()` から導いていたので、`Diff` を候補から落とすように
  した瞬間に**「Graph と Diff は同じ領域」を説明した腕が一つも踏まれないまま緑に
  なった**（テストの中のコメントだけがその腕の存在を語っていた）。**production の
  集合から範囲を導く見張りには、狙った要素が入っていることを先に assert する**
- **条件を狭めた変更で既存テストが何本もまとめて落ちたら、テストではなく条件の広さを
  疑う。** #54 では「差分の対象が無ければ `Diff` を候補から外す」で 5 本落ちたが、
  落ちたのは**条件が `None` の 2 つの意味（「この行では永久に出せない」と「まだ届いて
  いない」）を混ぜていた**からで、テストのほうは正しかった。**書き換える前に、落ちた
  5 本が何を守っていたかを読む** —— 適応させると、設計書が別に用意した追いつきの経路
  ごと踏めなくなる
- **テストで踏めない状態をコードに入れない。** 設計書に書いた状態でも、いまの機能では
  到達経路が無いなら入れず、送り先と理由を設計書に書いて次のタスクへ送る（`DiffState.stale`
  はハンク単位の書き込みが入るまで踏めないので送った）
- **到達不能な腕は、壊れていても既存のテストで見えない。** 上の裏返し。#49 では
  `to_argv` の `--force-with-lease` が refspec をそのまま埋めていて、`x` が
  `refs/heads/y` を追跡している形では `x:y:<oid>` に化けていた。**force を組む経路が
  無かったので、テストは全部緑のまま出荷されていた。** その腕を到達可能にする PR では、
  既存のテストが通っていることを根拠にせず、**実物の git に argv を叩き直す**
- **テストヘルパは、発行したジョブの返信も届けてから状態を渡す。** 届けないと
  `JobTracker` にジョブが残り、後続の同種の `Cmd` を `AppState::issue` が黙って落とす。
  #38 では、一覧の返信を届けないヘルパのせいで既存テストが `Cmd::LoadCommitDetail`
  単独を期待したまま通り、**一覧も頼んでいることを一つも見張れていなかった**。
  `Cmd` の期待値が「出なかった」なのか「落とされた」なのかは、`update` の戻り値
  だけからは読めない
- **逆も同じ。返信を届ける前に、そのジョブを発行する**（`test_util::reply`）。
  ランタイムでは `Cmd` が必ず `AppState::issue` を通るので、通さずに `Msg::*Loaded`
  だけ届けるヘルパは**実物では起きない形**を作る。#51 で世代を入れた瞬間、刻印の無い
  返信が「書き込みより前に頼まれたもの」として捨てられ、既存の 33 本が落ちた。
  **落ちたのは実装ではなくヘルパのほう** —— 直す先を間違えると、以後その経路の
  見張りが追いつきの腕を踏んだまま緑になる
- **「この見張りは本当に落ちるか」を確かめるとき、壊したつもりの置換が当たっていない
  ことがある。** `rustfmt` が畳んだ 1 行に対して複数行のパターンで置換すると、何も
  変わらないままテストが通り、**「見張りが効いていない」と誤読する**。置換したあとに
  `grep` で当たったことを確かめる
- **置換が当たっていて、それでも落ちないなら、疑うのは見張りか守りのどちらか。**
  上の 2 つ（置換が当たっていない / `--workspace` が打ち切った）を潰しても緑なら、
  **その見張りが狙った形を踏めていない**か、**壊した守りが最初から何もしていない**
  かのどちらか。実物で叩いて決める。
- **守りを消すと落ちることは、見張りが狙った経路を踏んでいる証拠にならない。** 上の
  逆から来る形。#78 の「書き込み中にモーダルを開き直すと古い写しが残る」の見張りは、
  守りを消すと確かに落ちたが、**開き直しを一度も踏んでいなかった** —— モーダルを
  開いたまま `A` を押すと `update_key` が `modal_key` へ渡すだけなので、
  **何も起きないのに `assert!(state.modal.is_some())` が自明に通る**（1 枚目が
  そのまま残っているだけ）。落ちたのは別の経路から守りに届いていたからで、
  **コメントが根拠に挙げた 2 つの前提（`submit_exec` が実行前に閉じる / `A` に
  実行中の断りが無い）は、どちらを壊しても緑のまま**だった。
  **「落ちた」で確かめ終わりにせず、コメントが挙げた前提を 1 つずつ壊す。**
  経路の途中の状態（ここでは「`submit_exec` が閉じたこと」）を `assert` で押さえ、
  **同じ値で並ぶ 2 つを区別できる形にする**（1 枚目を `Listed` にしておくと、
  開き直した 2 枚目が `Waiting` に戻ることが別物の証拠になる）
- **見張りが浅い側。** #65 では「一覧が枠に入りきらない」を 8 本 × 80x14 で見張ったが、
  そのサイズでは 5 行出るので**直す前も後も通った**。**実物で境目を測ってから書く**
  —— pty で本数と端末の高さを振ると 30 本 × 80x14 で 0 行になり、そこを踏むテストに
  して初めて落ちるようになった。**机上で選んだ値は境目をまたがない。**
- **守りが何もしていない側。** #73 では `git config` の argv に置いた `--` を
  「`-` 始まりの login を弾く」と書いたが、**外してもテストが通った** —— `git config`
  はキーより後ろをオプションとして読まないので、値が `--global` でも `-4` でも
  `--` の有無で結果が同じだった（一時リポジトリで実測）。grep で置換は当たっており、
  テストも実 git を叩いていたので、上の 2 つでは説明が付かない。**直すのは見張りでは
  なく、守りだと書いた記述のほう。** 「守りを根拠に書く前に、その守りが何を守って
  いるかを数える」（`rust-coding.md`）の**検出経路がこれ** —— 実装を壊して落ちない
  ことが、その守りが空振りだというサインになる。
- **上限の無い入力に「いちばん長い形」は作れない。そのぶん余白まで見る。**
  `owner/repo` も login も host も長さに上限が無いので、幅の見張りは**現実的な
  fixture 1 つ**で測るところまでしかできない（#73）。`contains` だけだと隣の要素と
  隙間なく並んだ状態で通り、1 桁伸びた瞬間に落ちるものが見えない。**逆に折り返しを
  見張るときは、fixture が境目を越えているかを先に assert する** —— #110 では
  `github.com` と短い login のコマンドが箱に収まり、wrap を外しても緑だった
- **「この見張りは本当に落ちるか」を実装を壊して確かめるとき、`cargo test --workspace` は
  最初に失敗したターゲットで打ち切る。** 後続クレートの結果が出ないまま「落ちなかった」と
  誤読する。`--no-fail-fast` を付けるか、`-p <crate> --lib <テスト名>` で対象を絞る。
  **ただし `mewgit-tui` はその形で絞れない** —— ディレクトリ名は `crates/mewgit-tui` だが
  **パッケージ名は `mewgit`** で、しかも lib ターゲットが無い（bin だけ）。`-p mewgit-tui`
  は `did not match any packages`、`-p mewgit --lib` は `no library targets found` で落ちる。
  こちらは **`cargo test -p mewgit --bin mewgit <テスト名>`**。
  **`--no-fail-fast` は `--` の前に置く。** あれは cargo の引数なので、`-- --no-fail-fast`
  と書くと libtest が受け取って**引数エラーで落ち、テストが 1 本も走らない**。#96 では
  変異を回すスクリプトがこの形で、**6 件とも「緑のまま = 見張りが効いていない」と
  報告した**（実際は全件が狙いどおり落ちる）。上の「壊したつもりの置換が当たって
  いない」と同じ族だが、**あちらは壊し方、こちらは走らせ方**。
  **変異のループでは「何本走ったか」を必ず突き合わせる** —— `test result:` の行を
  読み、0 本なら落ちたのではなく**走っていない**。**数えるのは `passed` + `failed`**
  —— 対象を 1 本に絞った回は `test result: FAILED. 0 passed; 1 failed;` になるので、
  `passed` だけを足すと**狙いどおり落ちた回が「走っていない」に見える**（#101 で
  5 件をこの形で読み違えた）
- **変異は実装だけでなく、テスト自身の入力にも掛ける。** 上のどの項目も「実装を壊す」
  話で、**テストから打鍵や入力を 1 つ消して落ちるか**は見ていなかった。#96 では
  「`r` を押すと落とした行に、飛んでいた答えが入る」を見張るつもりのテストが、
  **`press(state, 'r')` の 1 行を消しても緑**だった（`/code-review` が拾った）。
  実装側を壊すと落ちはするので、**実装の変異だけでは「その入力を踏んでいる」証拠に
  ならない**（#78 の「守りを消すと落ちることは証拠にならない」の、入力側の版）。
- **否定を見る assert は、入力を 1 行も書かなくても自明に通る。** 上の項目の
  「テストの入力を消して落ちるか」で見つかる形だが、**否定のテストは書いた瞬間から
  そうなっている**。#98 では「`branch.<name>.merge` が無ければ追跡先は `None`」の
  見張りから**入力の `git config` を消しても緑**だった（`None` は何も設定しなくても
  成り立つ）。実装側の現実的な変異（`merge` を要求しない形に変える）は捕まえるので、
  **実装を壊すだけでは気付けない**。**肯定へ変わるところまで 1 本で見る** ——
  同じリポジトリで `merge` を足すと `Some` になることを続けて assert すると、
  入力が効いている証拠がテストの中に入る。
- **主語が「起きる」でも、その状態が組めるかを産出元から数える。** 上の姉妹形で、
  #96 の原因のほう。「落とした行に、飛んでいた答えがそのまま入る」と設計書と doc の
  **3 箇所**に書いたが、**扇形の対象は「集計を持っていない行」から作られる**ので、
  答えが飛んでいる行はそもそも集計を持たない —— **組めない状態を 3 箇所で説明して
  いた**。「安全だ」と書いた場所を疑う規約（`rust-coding.md`）は**危なくない側**しか
  見ておらず、**「こう起きる」と書いた側**にも同じ検算が要る。**数えるのは状態の
  産出元** —— その値を作る関数が何を選んでいるかを読む。
- **テストを削るとき、「生存側が同じ失敗を捕まえる」を読んで決めない。生存側を残した
  まま実装を壊し、落ちることを確かめる。** 上の項目はどれも「足す・残す見張り」の話で、
  **削る側にこれを向けたことが無かった。** #82 で 27 本を削ったうち、読みだけで決めた
  2 本が外れた。**`auth/ssh.rs`** —— `assert_eq!(resolve_with(Opaque, ..),
  resolve_with(default(), ..))` を「どちらの腕も同じ `SSH_BIN` から同じ文字列を組むので
  **自分自身と比べているだけ**」と読んで等価 assert に置き換えたが、比べているのは
  2 つの**実行**で、`Opaque` 側だけが独立に失敗しうる（落とし先を起動できない値に
  変えると、置き換えた側では 19 本とも緑のまま通った）。**`modals/input.rs`** —— 削った
  2 本が唯一の見張りで、`.scroll((0, scroll_x))` を外しても `x: input_area.x +
  cursor_col` を外しても tui の 197 本が全部通った。**どちらも変異を 1 回入れれば
  見えた。** 逆に、変異で確かめてから削ったもの（`Reload` の両方向・
  `worktree_is_current`・`REQUIRED`）は 1 件も外れていない。
  **削除の PR では、生存側を名指しするコメントを書いた時点でそれを叩く。**
- **共有ヘルパが試されていることは、その戻り値を使う配線が試されていることではない。**
  同じ #82 で、`modals::cursor_col` に単体テストが 2 本あるのを根拠に `Input` モーダルの
  横スクロールとカーソル桁のテストを削ったが、**戻り値を `Paragraph::scroll` と
  `set_cursor_position` に渡す配線は `render` ごとに別**で、`Input` 側はその 2 本が
  唯一の見張りだった（`CommitMessage` の同名テストは別の `render` を見ている。あちらの
  `a_tiny_terminal_does_not_panic` のコメントが「編集中のモーダルごとに 1 本ずつ見る」と
  既に書いていた）。コーディング規約（`rust-coding.md`）の「共有先に寄せるときは、その基盤の暗黙の前提が
  新しい利用者にも成り立つかを確かめる」の**裏側** —— あちらはヘルパの前提、
  こちらは**呼ぶ側の数**。
- **書き直しは削除と同じ危険を持つ。旧実装が持っていた責務を数え上げる。**
  「テストを削るとき」は削除の話で、書き直し（同じものを別の形で出す）には手掛かりが
  無い。
  #86 では PRs ペインを書き直したとき、旧実装が `check_lines` の中で当てていた
  `theme::selected()` の 1 行が**消す判断の巻き添えで**落ち、`j` / `k` で画面が変わら
  ないのに `o` はカーソル行を開く状態で出荷しかけた。#54 では空表示の文言を組み直して
  既にあった `files_placeholder` の**失敗の腕を写しそこね**、読み込みに失敗すると
  永久に「読み込み中…」を出した。**入口は `git show main:<file>`**。同じ問いに答える
  関数が既にあるなら、書き直さずに呼ぶ
- **書き手が名前を変える経路を持つなら、読み手のテストにその形を 1 本入れる。**
  #107 では取り出しがローカルを `bob/main` にして `merge` に `refs/heads/main` を書く
  のを、**書いた側（#106）は知っていたのに、読む側はローカル名で組んでいた**。
  fixture がどれも「ローカル名 = リモート名」だったので緑
- `mewgit-core` の git 系は `tempfile` に実リポジトリを作って統合テスト。helper は
  `crates/mewgit-core/src/test_util.rs` の `TestRepo`。`test-util` feature でのみコンパイル
  され、`mewgit-core` は自分自身を dev-dependency に書いて有効にしている。ここを使う
  クレートは dev-dependency 側で `features = ["test-util"]` を付ける（付けないと
  `cargo test -p <crate>` 単体で「feature の後ろに隠れている」と言われる）。
  リポジトリは `git` CLI で作り、
  `GIT_CONFIG_NOSYSTEM` / `GIT_CONFIG_GLOBAL` / `HOME` で実行環境の設定を持ち込まない
- `TestRepo` はコミット日時を実時間ではなく固定カウンタから与える（`git` を 1 回叩くごとに
  60 秒進む）。実時間だと連続したコミットが同じ秒に落ち、`Sort::TIME` での並びが揺れる。
  author 日時と committer 日時には同じ値が入るので、両者が食い違うケースを踏みたいときは
  `git commit --amend --date` で author 側だけずらす
- 非 UTF-8 のコミットメッセージは `-c i18n.commitEncoding=ISO-8859-1` を付けて `-F` で
  渡さないと作れない。git は「UTF-8 ではない」と判断したメッセージを latin-1 とみなして
  UTF-8 に変換するので、素直に作ると生バイト列がオブジェクトに残らない（git 2.55 で確認）。
  `-q` も要る。summary の echo が `TestRepo` の UTF-8 検証に当たる
- 非 UTF-8 の**ファイル名**はワークツリーに作れない。macOS の APFS が
  `Illegal byte sequence` で弾く。`git update-index --add --cacheinfo` で index にだけ
  入れれば作れて、しかも「staged で追加 / ワークツリーからは消えている」になるので
  staged 側と unstaged 側を 1 回で踏める（`TestRepo::add_raw_path_to_index`）。
  パスを argv に載せるので `TestRepo::git` は `AsRef<OsStr>` を取る
- **`mv` でファイルを戻すと cargo が再ビルドしない。** `mv` は元の mtime を持ち込むので
  ビルド成果物より古くなり、fingerprint が変わらずに古いバイナリが走る。「この見張りは
  本当に落ちるか」を確かめるために実装を一時的に書き換えたときは、戻したあと `touch`
  してから流し直す
- **その戻しに `git checkout <file>` を使わない。** 戻る先は**コミット**であって、
  壊す直前の状態ではない。同じファイルに未コミットの修正（レビュー指摘の適用など）が
  あると丸ごと消える。#68 では `/simplify` の適用を全部消して replay する羽目になった。
  `cp` で退避して `cp` で戻し、戻したあと `touch` する（上の項）。
  **戻し方はループの中で 1 つに揃える。** #83 で 2 回目を踏んだのは、変異を連続で回す
  **1 つのコマンドの中で 4 件を `cp` で戻しながら、最後の 1 件だけ `git checkout` を
  書いた**から —— コミット済みの直前のコミットまで戻り、`/simplify` で入れた共有先が
  丸ごと消えた。**規則を知っていても、戻し方が混ざっていると踏む。**
- **退避ファイルの名前にはパスを入れる。** `basename` で退避すると、`app/keys.rs` と
  `app/update/mod.rs` と `ui/mod.rs` を並べた瞬間に **`mod.rs` が衝突して片方が消え**、
  戻すときに**別ファイルの中身を書き込む**（#94 で `update/mod.rs` へ `ui/mod.rs` を
  書き戻し、`mod update;` が「ファイルが見つからない」で落ちた）。`$(echo $f | tr / _)`
  で潰す。上の項目は**戻し方**を揃える話で、**退避先の名前**は見ていない。
  **変異を回す前にコミットしておけば、これは事故ではなく手戻りで終わる。**
- `Path` 同士の `assert_eq!` は末尾の区切りを無視するので、パスの正規化はテストできない。
  git2 の `workdir()` / `path()` は `/…/repo/` と末尾を付けて返すため、正規化を確かめる
  ときは `to_string_lossy()` で文字列に直して見る
- **`auth` のテストは実物の `ssh` を叩く。** `-F` に一時ファイルの ssh_config を渡すと
  `/etc/ssh/ssh_config` ごと無視するので、実行環境から切り離せる（stub は要らない）。
  設定ファイルを 1 枚書くだけのヘルパは `test_util::temp_file`
- `graph` は固定のコミット列に対する `cells` の期待値テストを必ず追加する
- GitHub API は `wiremock` でモック。実 API は叩かない
- **wiremock のテストは出荷側の `reqwest::Client` を使い回さない。** `shared_http` は
  プロセスで 1 つなので、**死んだ `MockServer` 宛ての idle 接続がプールに残り、OS が
  同じポートを次のサーバに割り当てるとそこへ送って `error sending request` で落ちる**。
  本文を 1 行も変えずにテストを 7 本足しただけで、既存の
  `pr_detail_counts_every_check_state_and_does_not_fold_them` が **15 回中 2 回**落ちた
  （main は 6 回中 0 回、`pool_max_idle_per_host(0)` で 12 回中 0 回。#90 で実測）。
  ヘッダとタイムアウトは `http_builder` として出荷側と共有し、テストのクライアントだけ
  プールを切ってある。**サーバが死なない出荷側では起きない**ので本番は切らない。
  **揺れを持ち込むのが本文ではなくテストの本数**という形なので、**揺れが自分の差分由来かは
  `git worktree` で main を切って同じループを回して比べる**（`cargo test -p <crate> --lib`
  を 6〜12 回）
- `git_exec::to_argv` は純粋関数なのでユニットテストで全 `GitOp` をカバーする
- **`runtime::run` のループテストは、非同期の返信が届く順序に依存できない。**
  `stream::iter` で渡したキー入力は即座に ready なので、リーダースレッドの返信
  （`Msg::LogLoaded` など）より先に処理される。「1 ページ目が積まれている前提」の
  ループテストは書けない。状態を用意してから遷移だけを見たいときは、ループを回さずに
  `update` / `layout` を直に呼ぶ
- `mewgit-tui` の描画は ratatui の `TestBackend` にレンダリングしてバッファを検証する。
  取り出しは `terminal.backend().to_string()` を使う。セルを自前で走査すると全角文字の
  2 セル目が空白として混ざる（「新しい通知」→「新 し い 通 知」）
- 型だけを定義するタスクでも、その型で実際の操作を 1 つ組み立てるテストを書く。
  組み立てられないなら型が間違っている（「この確認モーダルに入れる値を作れるか」など）
- テストを書かない例外は、端末の raw mode 切替・復元と `main.rs` の配線だけ。実端末が必要で単体テストできないため
