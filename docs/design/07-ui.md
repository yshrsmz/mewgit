# 07. ui: 画面・ペイン・モーダル・キーバインド

## レイアウト

目標の形は GitKraken に寄せる。**左の広い領域が「グラフ または diff」、右の狭い領域が
「いま左で選んでいるものの中身」**という 2 列で、左右のどちらも中身が入れ替わる。

```
┌ owner/name  main ↑1 ↓0   [acct: user_shortcode @ github.com]  ⟳ fetch ─┐
│                                   │ Working tree (3)                  │
│  Graph                            │  Staged                           │
│  ◇ WIP (3)                        │   M src/main.rs                   │
│  ● [main] {origin/main} Add ...   │  Unstaged                         │
│  │ ● <v1.0> Release              │   M src/graph.rs                  │
│  ├─╮ Merge feat/y                 │  Untracked                        │
│  │ ● Fix ...                      │   ? notes.md                      │
│  ● │ ...                          │                                   │
├───────────────────────────────────┴───────────────────────────────────┤
│ REBASE 3/7 (edit)  [c]ontinue [s]kip [a]bort      ?:help  q:quit     │
└───────────────────────────────────────────────────────────────────────┘

右でファイルを選んで Enter → 左が Diff に差し替わる（Esc で戻る）

┌ owner/name  main ↑1 ↓0 ────────────────────────────────────────────────┐
│                                   │ Working tree (3)                  │
│  Diff: src/main.rs                │  Staged                           │
│  @@ -1,4 +1,6 @@ fn main() {      │   M src/main.rs                   │
│   fn main() {                     │  Unstaged                         │
│  -    println!("old");            │   M src/graph.rs                  │
│  +    println!("new");            │  Untracked                        │
│                                   │   ? notes.md                      │
├───────────────────────────────────┴───────────────────────────────────┤
│                                                   ?:help  q:quit      │
└───────────────────────────────────────────────────────────────────────┘
```

- **左（幅 60%）は Graph か Diff のどちらか。** `focus == Pane::Diff` のあいだだけ Diff。
  差し替えであって分割ではないので、**グラフに使える領域の大きさは変わらない**
  （`ui::graph_rows` と `Msg::Layout` に手を入れずに済む。01 の「グラフの行」）
- **右（幅 40%）は左で選んでいるものの中身。** 目標は「WIP 行を選択中 → Working tree、
  コミットを選択中 → そのコミットの詳細（メッセージ + 含まれるファイル一覧）」。
  上部のタブ `Branches | Stash | PRs` はそれぞれのタスクで足す
- 最下部: ステータスバー。進行中操作、実行中ジョブ、直近通知、キーヒント

### どこまで実装したか

目標の形にはまだ届いていない。**この節を読んだら、いまどの段階かをここで確かめる。**

| 段階 | 状態 |
|---|---|
| 左に Graph、右に Working tree の 2 列 | 済み（#22） |
| 左を Diff に差し替える経路（右でファイル選択 → `Enter`） | **このタスク（M2 の diff）** |
| ハンク単位の stage / unstage / discard | M2 の次のタスク |
| コミット詳細を右ペインに出す（いまはグラフの下に展開） | 未。下の「コミット詳細の置き場所」 |
| グラフ先頭の WIP 行と、そこを選んだときの staging | 未。M2 の commit のタスクと一緒に決める |
| 右上のタブ `Branches \| Stash \| PRs` | 未。各タブのタスク |

**コミット詳細の置き場所。** いまはグラフペインの中で `Enter` により下部へ展開している
（M1 で入れた）。目標の形では右ペインに出す。移すときに動くのは
`panes::graph::shows_detail` / `ui::graph_rows` / `Msg::Layout` で、グラフの高さが
展開で変わらなくなるぶん**単純になる**。ただし右ペインが「WIP かコミットか」で
中身を変える必要が出るので、WIP 行の導入と同じタスクでまとめて行う。それまでは
下部展開のままにする（片方だけ動かすと、右ペインが常に Working tree のまま
コミット詳細を出す先が無くなる）。

端末幅 < 100 のときは右ペインを隠し、`Tab` でペインを全画面切替する。**この分岐は M6。**
それまでは幅によらず 60/40 に割る。幅で隠すのを先に入れると、80 桁の端末から右ペインへ
到達する手段が無くなる（全画面切替が同じ M6 のタスクなので、片方だけ入れられない）。

**まだ無いペインのぶんを空枠で確保しない。** いまは `Working tree` が右列をまるごと使う。
`Branches | Stash | PRs` の上下分割は、そのタブを実装するタスクで入れる。先に枠だけ
置くと、中身の無い箱に高さを取られる。

## ペインとフォーカス

`Pane` の定義は 01（`app`）にある。フォーカスは状態なので core が持ち、`ui` は描画するだけ。

- `Tab` / `Shift+Tab` で巡回。**巡回に入れるのは実装済みのペインだけ**で、順序は
  `Pane` の宣言順に従う。未実装のペインに移れると、キーを受け取る先が無い画面に
  入り込む。ペインを実装したらその一覧に足す（`app` 側の定数）。`1`〜`5` の直接
  ジャンプは M6（`Modal::Help` と同じタスク）
- **フォーカスのあるペインは枠を強調する。** 巡回できるペインが 2 つ以上あるのに
  どちらが受けるか判らないと、`s` や `x` が別のペインに飛んだように見える
- **左の領域に Graph と Diff のどちらを描くかは `focus` だけで決める。** `focus == Pane::Diff`
  なら Diff、それ以外は Graph。「どちらを見せているか」を別に持たない。持つと `focus` と
  食い違う状態（Diff を見せているのにキーは Graph が受ける）が表現できてしまう
- 各ペインは `trait PaneView { fn render(&self, f, area, state: &AppState); }` を実装する。
  キー処理は `app::update` 側にあり、`ui` は `Cmd` を作らない（不変ルール 2）
- **描画に使える行数は `ui` が出す。** `app` はスクロール位置を決めるのに要るが
  （01 の「グラフの行」）、レイアウトを知っているのはここだけ。`ui::graph_rows(state)` が
  描画と同じ関数からペインの高さを出し、`Msg::Layout` に載せて渡す。ランタイムが
  描画の直前に `viewport` と比べて、違うときだけ流す（01 の「ランタイム」）。
  引数は端末サイズと「詳細を出すか」の 2 つだけにする。`&AppState` を丸ごと受けると
  詳細の中身を見る余地が残り、詳細が届いた瞬間に行数が変わってグラフが跳ねる

## Graph ペイン

- 1 行は `短縮 Oid  ラベル  summary`。左のレーン罫線は `GraphRow.cells` から描く。
  1 マスの文字は `(Cell::vertical, Cell::horizontal)` の組から決まる（対応表は 06）。
  色は縦成分の `ColorId` を palette に写したもの。縦成分が無く横線だけが通るマスは
  横成分の色を使う。コミット本体のマスは常に縦の色。ASCII フォールバックの置換表も
  ここに持つ（06 の「ASCII フォールバック」）
- レーンは 1 本を 2 桁で描く。レーン間の桁は、左のセルが右へ、右のセルが左へ
  伸びているときだけ `─` で埋める（`Horizontal::goes_right` / `goes_left`）。
  その桁の色は左のセルの横線の色
- 罫線の桁数は、そのフレームで描く行のレーン数の最大に揃える。スクロールで
  桁が揺れるが、読み込み済みの全行で最大を取ると複雑な履歴で桁が育ち続ける。
  上限は設けず、はみ出す分は ratatui のクリップに任せる
- 表示するのは `scroll` から画面の高さぶんだけ。カーソル行は反転
- コミットが 1 つも無いときは、読み込み中なのか本当に空なのかを出し分ける
  （`GraphState.loaded_all` で判る）

### 詳細の展開

`Enter` で選択コミットの詳細をペインの下部に開く。もう一度押すと閉じる。

```
│ ● [main] {origin/main} Add ...    │
│ │ ● <v1.0> Release                │
├───────────────────────────────────┤
│ commit a1b2c3d4e5f6...            │
│ Author: Name <mail>  2026-09-06 …│
│ Commit: Name <mail>  2026-09-06 …│
│ Parent: d4e5f6a                   │
│                                   │
│ Add the thing                     │
```

- 高さは固定 `DETAIL_ROWS` 行。ただしグラフに最低 `MIN_GRAPH_ROWS` 行は残し、
  詳細に `MIN_DETAIL_ROWS` 行を取れないなら開かない。前者は端末を縮めたときに
  詳細だけが残るのを防ぐため、後者は 1 行だけ取って区切り線で埋まり、グラフの行を
  失って何も出ない状態にしないため
- **詳細の領域を取るかの判定は 1 つ**（`shows_detail`。展開していて、かつ行がある）。
  行数を出すときと描くときで別に決めると、`app` に渡した行数と実際に描く行数がずれる
- メッセージは描ける行数までしか組まない。折り返しで増えることはあっても減ることは
  ないので、見える行は落ちない。revert やマージの本文は数百行になりうる
- 出す値は `GraphState::fresh_detail()`（01）。**カーソルの指すコミットの oid と
  `detail.oid` が一致するときだけ中身を出す。** 一致しないのは、まだ届いていないか
  失敗したときなので、`JobTracker` に `LoadCommitDetail` が居れば「読み込み中…」、
  居なければ「詳細を読み込めませんでした」を出す。空のグラフの出し分け（上）と同じ形
- 日時はコミット自身のタイムゾーンで出す（`Timestamp.offset_minutes`）。`git show` と
  同じで、見る人の環境のタイムゾーンには寄せない。整形は `ui::time`。日時のクレートは
  足していない（この 1 箇所のためにサプライチェーンを増やさない）
- ファイル一覧は出さない。**コミットに含まれるファイルの一覧は右ペイン**（コミット詳細を
  そちらへ移したとき）、**選んだファイルの diff は左の Diff ペイン**に出す。`DiffTarget::Commit`
  を読むのはその段階で、いま実装するのはワーキングツリーの diff だけ（上の「どこまで実装したか」）

## Worktree ペイン

```
│ Working tree (3)                  │
│  Staged                           │
│   M src/main.rs                   │
│  Unstaged                         │
│   M src/graph.rs                  │
│  Untracked                        │
│   ? notes.md                      │
```

- 区画の見出しと、その中のファイルを 1 行ずつ並べる。**空の区画は見出しごと出さない。**
  カーソルが飛ばす区画を描いても、選べない行が増えるだけ
- 1 行は `<種別 1 文字> <パス>`。rename は `<旧パス> -> <新パス>`。種別は
  `M A D R C T ?` と、conflicted の `U`
- カーソル行は反転。カーソルの位置（区画と添字）は `WorktreeState` が持つ（01）
- パスは長いと右が切れる。左を切って `…/` にするのは M6 の狭いレイアウトで決める
- 見出しの `Working tree (n)` の `n` は全区画の合計
- **スクロールはグラフと違い、状態を持たずに毎フレーム導く**（カーソルが窓に入るまで
  下へずらすだけ）。そのぶん「下端から上へ戻るときにカーソルが最下行に貼り付く」癖が
  残る。グラフはこれを避けるために `scroll` を状態に持ち `Msg::Layout` で `viewport` を
  運んでいる（01）。右ペインにも同じ形を入れるかは M6（狭いレイアウト）で決める。
  それまでは劣る挙動で行く
- キーは `s`（stage）/ `u`（unstage）/ `x`（discard）。`x` は必ず `Modal::Confirm` を
  通す（不変ルール 5）。何が起きるかは区画で変わるので、**確認の本文も区画ごとに
  変える**（untracked は「ファイルを削除します」、tracked は「HEAD の状態に戻します」）

## Diff ペイン

```
│ Diff: src/main.rs                 │
│  @@ -1,4 +1,6 @@ fn main() {      │
│   fn main() {                     │
│  -    println!("old");            │
│  +    println!("new");            │
```

- **左の領域に、Graph と差し替えで描く**（上の「レイアウト」）。右のワーキングツリーは
  出したままにするので、どのファイルを見ているかが一覧の側でも判る
- 枠のタイトルは `Diff: <パス>`。rename は `<旧> -> <新>`。**対象を必ず出す。**
  左が差し替わっているので、出さないと何の diff かを画面から辿れない
- 中身はハンクの見出し（`@@ ...`）と行を順に並べる。行の先頭は ` ` / `-` / `+`。
  ファイルが複数のときはファイルの見出しも挟む（`DiffTarget::Commit` を出す段階で要る。
  ワーキングツリーの diff は 1 ファイルに絞るので、いまは見出しが 1 つだけ）
- **折り返さない。** 長い行は右で切る。diff は桁の揃いが意味を持つので、折り返すと
  どの行がどの行に対応するのか読めなくなる
- **`content` は `Vec<u8>` なので、描くときにその場で lossy にする**（02 の
  「ハンクの持ち方」）。`\t` は **8 桁のタブストップで空白に開く**。1 個の空白に潰すと
  インデントが崩れて、上下の行の対応が読めなくなる。桁は**先頭の `-` / `+` / ` ` を
  除いた本文の先頭から**数える（記号を含めて数えると、変更行と文脈行でタブストップが
  1 桁ずれる）。`\r` は落とす。落とさないと CRLF のファイルで制御文字が画面に出る
- カーソルはハンク単位（`DiffCursor`）。`j` / `k` で次のハンクへ移る。ハンク単位の
  stage / unstage / discard はカーソルの指すハンクに効く（次のタスク）
- 空のとき（バイナリ、mode だけの変更、まだ届いていない）は理由を出す。読み込み中と
  「差分がありません」の出し分けは Worktree ペイン・グラフの空表示と同じ形
- 入るのは Working tree ペインで `Enter`、出るのは `Esc`。`Tab` の巡回にも入る

## モーダル

`Modal` の定義も 01 にある。複数行の入力は `app::TextBuffer` で持つ。ratatui の
ウィジェットや `tui-textarea` を状態として持たない（core が UI に依存するため）。
`ui` は `TextBuffer` を毎フレーム `Paragraph` などに写して描く。

- モーダル表示中はキー入力をすべてモーダルに渡す。`Esc` で閉じる
- `Confirm` は破壊的操作の前に必ず使う（force push、`branch -D`、discard、abort 系）
- モーダルは画面の中央に、下のペインを覆って描く（`Clear` を敷く）。覆わずに重ねると
  下の文字が透けて読めなくなる。`Confirm` は「タイトル / 本文 / `[y] 実行  [n] やめる`」の
  3 段で、**本文には対象（パス）をそのまま出す**。「選択中のファイル」とだけ書くと、
  カーソルがどこにあるか思い出せないまま `y` を押すことになる
- **枠の高さは折り返し後の行数を実測して出す**（`ui::wrapped`）。`桁数 / 幅` の
  切り上げで見積もると、単語境界で折れて増えたぶんを数え落とし、本文の末尾が黙って
  切れる。枠には空行を 1 行取ってあるので 1 行の不足は吸われ、2 行足りないときに初めて
  見える。`contains` を見るテストはどちらでも通るので、**末尾がキーの案内より上に
  あることまで見る**。行数は ratatui の `Paragraph::line_count`（描画と同じ
  `WordWrapper` を通る）から取る。unstable feature `unstable-rendered-line-info` が
  要るので `mewgit-tui` の `Cargo.toml` で有効にしている
- **測る `Paragraph` を組むのは `ui::wrapped` だけ。** 測るときと描くときで `Wrap` の
  設定がずれるのを防ぐためと、枠（`block`）を付けたまま測らせないため。`line_count` は
  枠の上下を行数に足す一方、**枠の左右ぶんを幅からは引かない**ので、枠付きで測ると
  外側の幅で折り返した行数が返り、直したはずの「末尾が切れる」に戻る
- **枠が食う幅と行数は `Block::inner` から出す。** `- 2` / `+ 2` と手で書くと、
  あとで `Padding` を足したときに折り返し幅だけが古いまま残る。高さは折り返してからで
  ないと決まらないので、幅の判る当て木（`Rect::new(0, 0, width, u16::MAX)`）を
  `Block::inner` に通して内側の幅と枠の行数を取る。グラフの詳細の見出しは枠を
  自分で持たないので、`inner.width` をそのまま渡す

## RebaseEditor

```
 pick   a1b2c3  Add feature
 squash d4e5f6  Fix typo
 reword 789abc  Update docs
 drop   ...
```

- `j/k` 移動、`J/K` で行を入れ替え、`p/r/e/s/f/d` でアクション変更、`Enter` で実行
- `reword` の行は `Enter` 前にメッセージ入力を求め、`RebasePlan` に持たせる
- 先頭行を `squash/fixup` にできない等の制約はエディタ内で検証し、赤で表示

## 既定キーバインド（抜粋）

| キー | 動作 | ペイン |
|---|---|---|
| `j/k` `g/G` `Ctrl-d/u` | 移動 | 共通 |
| `f` / `p` / `P` | fetch / pull / push | 共通 |
| `c` / `C` | commit / amend | Worktree |
| `s` / `u` / `x` | stage / unstage / discard | Worktree, Diff |
| `n` / `d` / `r` | branch 作成 / 削除 / リネーム | Branches |
| `Enter` | checkout / 詳細展開 / diff を開く | Branches, Graph, Worktree |
| `Esc` | Diff を閉じて Worktree に戻る | Diff |
| `i` | interactive rebase（選択コミットまで） | Graph |
| `y` / `v` | cherry-pick / revert | Graph |
| `z` / `Z` | stash push / pop | Worktree, Stash |
| `o` | PR をブラウザで開く | Prs, Graph |
| `N` | PR 作成 | Prs |

キーマップは `config.keymap` で上書き可能（08 参照）。

## 描画の原則

- `render` は `&AppState` のみ参照する
- 長い一覧は `ratatui` の `ListState` / 自前 viewport で可視範囲だけ描画
- 色は `theme` 構造体経由で参照し、直接 `Color::Red` を書かない。文字列から
  `Style` への変換は `ui::theme::style`（08 の「スタイル指定」）。ペインごとに
  持たない
- 進行中ジョブがあるときはヘッダ右端にスピナー（`Tick` で回転）
